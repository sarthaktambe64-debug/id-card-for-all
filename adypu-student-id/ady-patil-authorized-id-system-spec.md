# Ajeenkya DY Patil ID Card Issuance System

This document defines the production path for turning the editable card template into an authorized institutional ID issuance system.

## Purpose

Create student ID cards only from institution-controlled student records, with approval, audit history, print control, and a barcode payload generated by the approved backend system.

## Required Roles

- Administrator: manages batches, templates, and issuing officers.
- Data operator: imports or verifies student records.
- Approver: reviews photo, name, UID, branch, class, year, and batch before printing.
- Issuing officer: performs final issue from the authenticated system.
- Auditor: reviews issue history and reprint logs.

## Required Student Record Fields

- Full name
- UID or enrollment number
- Branch
- Class or semester
- Academic year
- Photo
- Record status
- Batch ID
- Issuing officer
- Approved timestamp
- Issued timestamp

## Issuance Workflow

1. Import records from the student information system.
2. Validate required fields and photo quality.
3. Generate a draft card proof.
4. Review and approve the card proof.
5. Generate barcode payload from the backend.
6. Issue final card through an authenticated print/export action.
7. Store audit event with issuer, timestamp, batch, record ID, and template version.
8. Log every reprint separately.

## Barcode Rules

The barcode should not be manually typed in the visual template. It should be generated by the backend from a signed payload such as:

```json
{
  "institution": "ADYPU",
  "recordId": "internal-student-record-id",
  "uid": "student-uid",
  "batch": "batch-id",
  "issuedAt": "iso-timestamp",
  "templateVersion": "template-version"
}
```

The visible barcode should encode only the approved payload or an opaque lookup token. Avoid exposing private student data directly in the barcode.

## Security Controls

- Require staff login.
- Require role-based access for final issue.
- Keep draft and final outputs separate.
- Lock final issue until approval is complete.
- Store template version with every issued card.
- Record every print and reprint.
- Prevent editing after issue except through a replacement or reissue workflow.
- Keep student photos and records in approved institution storage.

## Template & Asset Files

- `ady-patil-college-id-editable.html`: Interactive institutional ID issuance application with native Code 128 barcode generator, CR80 PVC print stylesheets, audit simulation, and multi-record controller.
- `ady-patil-college-id-sample-template.svg`: Standalone 1:1 vector CR80 ID card source embedding the official crest and scannable barcode.
- `assets/ady-patil-crest-official.jpg`: High-resolution source master of the official Ajeenkya D Y Patil Group crest.
- `assets/ady-patil-crest-cropped.png`: Proportional card-header crest asset (omits bottom text banner to match card layout).
- `assets/sample-student-photo.jpg`: Calibrated reference portrait asset for student record verification.

## Production Integration Needed

The current HTML file is a front-end print proof. For final production, connect it to:

- institution login
- student database
- approved photo store
- barcode generation service
- audit log database
- print queue or PDF renderer

Final issue should be enabled only by the backend after successful authentication, approval, and audit logging.
